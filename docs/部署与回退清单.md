# 部署与回退清单

> 用于比赛评审期锁定依赖、环境变量和可回退部署版本。

## 1. 依赖锁定

`requirements.txt` 全部使用精确版本（`==`），部署和本地测试使用同一套依赖：

```bash
python -m pip install -r requirements.txt
```

修改依赖后必须重新运行全量测试，并确认 `pip freeze` 与清单一致。

## 2. 环境变量清单

| 变量 | 必填 | 说明 |
|---|---|---|
| `LLM_API_KEY` | 是 | 上游模型 API Key |
| `LLM_BASE_URL` | 是 | 上游模型 Base URL |
| `LLM_MODEL` | 是 | 上游模型名称 |
| `APP_VISION_MODEL` | 否 | 视觉理解模型；配置后图片和扫描 PDF 才走真实识别 |
| `APP_ASR_MODEL` | 否 | 语音转写模型；当前验证 `qwen-audio-3.0-asr-flash`，配置后音频才走真实转写 |
| `APP_VISION_API_KEY` | 否 | 视觉模型专用 API Key；留空复用 `LLM_API_KEY` |
| `APP_VISION_BASE_URL` | 否 | 视觉模型专用 Base URL；留空复用 `LLM_BASE_URL` |
| `APP_ASR_API_KEY` | 否 | 语音模型专用 API Key；留空复用 `LLM_API_KEY` |
| `APP_ASR_BASE_URL` | 否 | 语音模型专用 Base URL；留空复用 `LLM_BASE_URL` |
| `APP_ASR_TRANSCRIPTION_MODE` | 否 | `auto` / `chat` / `native` / `dashscope`；`qwen-audio-*` 自动走 DashScope 原生 ASR endpoint，`qwen3-asr-flash` 走 `chat` |
| `STORAGE_BACKEND` | 否 | `local` 或 `s3`；生产建议 `s3` |
| `S3_BUCKET` | s3 时必填 | S3 兼容存储桶名 |
| `S3_PREFIX` | 否 | 对象存储前缀，默认 `workbench/` |
| `S3_REGION` | 否 | S3 区域，默认 `auto` |
| `S3_ENDPOINT_URL` | 否 | S3 兼容服务地址；留空使用云厂商默认 |
| `APP_HOST` / `APP_PORT` | 否 | 本地监听地址与端口 |
| `LLM_PREFER_PLAIN` | 否 | 结构化调用是否优先普通文本回退 |
| `LLM_DISABLE_THINKING` | 否 | DeepSeek V4 是否关闭思考模式 |
| `LLM_TIMEOUT` / `LLM_MAX_TOKENS` | 否 | 上游超时与单次生成上限 |
| `APP_ADMIN_TOKEN` | 否 | 站点管理令牌 |
| `APP_USERS_JSON` | 否 | 多用户账号文件路径 |
| `APP_NOTIFY_WEBHOOK` | 否 | 提醒推送 Webhook |
| `APP_TZ_OFFSET` / `APP_TIMEZONE` | 否 | 应用时区，默认东八区 |

`dashscope` 模式固定调用
`https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`，
即使 `APP_ASR_BASE_URL` 配置为 `compatible-mode/v1` 也能正常使用。

## 3. 发布前检查

```bash
python -m pytest tests/ -q
node --check app/web/static/app.js
node --check app/web/static/participants.js
python scripts/verify_media_models.py
```

`verify_media_models.py` 只有在配置了真实视觉/语音模型时才返回 0；未配置时返回 2，属于可接受的降级状态。

原 `qwen3-asr-flash` 计划于 2026-10 下线；当前切换的
`qwen-audio-3.0-asr-flash` 已通过真实调用验证。正式部署前建议再次运行
`scripts/verify_media_models.py`，并同步更新 `APP_ASR_MODEL` 与本文档。

## 4. 部署记录

每次发布必须记录：

- 应用版本（FastAPI `/api/health` 和 `FullPlan.version`）
- Git commit hash
- 依赖锁定文件是否变更
- 环境变量是否新增/删除
- 真实模型验证结果（如适用）
- 全量测试数量与结果

## 5. 回退流程

1. 打开 Render 项目 Deploys 页面。
2. 选择上一份已验证部署，点击 `Rollback`。
3. 回退后访问 `/api/health`，确认版本号回退到预期值。
4. 执行一次核心链路验证：上传文件 → 生成草案 → 确认分工 → 导出。
5. 若回退涉及环境变量，先在 Render Environment 中恢复旧值，再触发部署。

本地回退：

```bash
git log --oneline -5
git checkout <上一已发布 commit>
python -m pip install -r requirements.txt
python -m pytest tests/ -q
```

## 6. 对象存储启用

把 `STORAGE_BACKEND` 改为 `s3`，并配置 `S3_BUCKET` 后，方案 JSON、
导出附件和分享令牌会在写入本地 memory 的同时同步到对象存储；本地文件缺失时
会自动从对象存储恢复。部署前建议用生命周期策略清理 `artifacts/` 前缀下超过
48 小时的导出附件。
