秘圣淼 2026年8月11日 23:53
我们团队是怎么高效用这批算力的
参赛两周，我们复盘过一次自己的卡时流水：真正在跑模型的时间不到一半，
剩下的都耗在断线重连、环境没生效白跑、测量口径对不上重测这三件事上。
把这三个漏堵上之后，有效卡时占比提到了九成以上。分享一下我们的具体做法，
全部在 A2/A3 开发机上实测。
1. SSH 一步直达，断线不丢现场
登录节点跳计算节点，我们在 ~/.ssh/config 里配了 ProxyJump + 保活 + 连接复用：
Host login
    HostName <登录节点IP>
    User <用户名>
    ServerAliveInterval 30
    ServerAliveCountMax 6

Host npu
    HostName <计算节点IP>
    User <用户名>
    ProxyJump login
    ServerAliveInterval 30
    ControlMaster auto
    ControlPath ~/.ssh/cm-%r@%h:%p
    ControlPersist 10m
之后 ssh npu 一步到卡，scp/rsync 自动走双跳，ControlMaster
复用连接免去重复握手，体感差别很大。
2. 开跑前过"三道门"，废批在第 0 分钟拦下
我们浪费最多卡时的方式不是跑得慢，而是跑了个寂寞。三种坑各踩过至少一次，
每次白烧 30～120 分钟：补丁其实没编进二进制、环境变量其实没被读到、
测的口径和自己以为的不一致。后来所有批量脚本开头强制过三道门：
门 1：改动真的编进去了吗？
make -j && strings ./server | grep MY_TAG_0811 || { echo "改动没编进去"; exit 1; }
在源码里埋一个本次改动的版本标记，产物里 grep 得到才放行。
门 2：环境变量真的生效了吗？
不信 wrapper 脚本"应该会 export"——让程序启动时把实际读到的配置打印进日志，
脚本 grep 校验。我们踩过"env 只在示例脚本里被 source、正式脚本根本没读"的坑，
两批实验作废。
门 3：口径先对再上量。
先跑 30 秒小样本确认输出格式和统计口径，再开大批次。装上三道门之后，
一次 8 连跑的废批在第 0 分钟就被拦住，省下的正是最贵的整卡时段。
3. 让每张卡时都产出可比数据
对比实验只用同一个二进制、同一份输入跑双臂，交替执行防环境漂移；
每臂至少 3～4 次看分布而不是单次均值，首次 warmup 丢弃；每条结果落盘时
用 date 记录真实时刻。这样跑出来的数据不用回头重测，等于卡时直接翻倍。
4. 任务做成可断点续跑，A3 排队就切 A2
结果按批落盘、脚本幂等（重跑自动跳过已完成部分）之后，"在哪张卡上跑"
就不重要了：A3 排队高峰直接切 A2（官方同步只有 70% 使用率），
长任务丢到夜间时段，白天的卡留给需要交互调试的活。
5. 一行"卡时哨兵"，人睡觉卡干活
卡死空转是最贵的浪费。登录节点挂一行 cron，每半小时看进程和产物
是否还在推进，停滞就写告警：
*/30 * * * * pgrep -f run.sh > /dev/null && find ~/results -mmin -35 | grep -q . || echo "任务停滞 $(date)" >> ~/idle-alert.log
配合任意能到手机的消息通道，出事秒知道，不用整晚盯终端。

以上没有任何门槛，Claude code或者Codex或者Zcode等等半小时能全部配完，祝大家都拿到好成绩！

【vLLM-Omni 子赛道经验分享】跑通官方评测踩到的一些文档/环境坑,供参考

各位老师好,我们在 910C + 官方镜像(vllm-omni:v0.25.0-a3)上跑 vLLM-Omni 子赛道评测时踩了些文档和环境层面的坑,整理出来分享,说的不对的地方还请海涵:

1. 官方 pytest 文档笔误:--num-warmup(单数)实际 CLI 参数是 --num-warmups(复数)
2. Seed-TTS 的 SIM 会被静默跳过:设了 SEED_TTS_SIM_EVAL=1 还需加 --seed-tts-file-ref-audio 指定参考音频,否则 SIM 整列静默缺失
3. WER 评测联网会卡死:WER 初始化会访问 HuggingFace,离线环境记得加 HF_HUB_OFFLINE=1
4. 两个"改了也没用"的配置:connector_get_sleep_s(minicpmo 链路无 Python 消费端,轮询硬编码 1ms)、codec_chunk_ramp(仅适配 Qwen3-TTS)
5. 评测客户端偶发崩溃:跑完后偶尔报 corrupted size vs. prev_size(glibc teardown),不影响已产出结果,重跑即可
6. serve 启动路径:从 /tmp 启动 vllm serve,避免 /vllm-workspace 目录遮蔽 vllm 包 import
7. 镜像内装依赖:pip install stepaudio2-minicpmo + pip install step-audio2 --no-deps(防覆盖 torch/torch_npu)

祝大家评测顺利,一起加油!🚀
