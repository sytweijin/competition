# 演示脚本：五步多模态驱动（P2 版）

> 更新时间：2026-08-22
> 定位：把比赛 Demo 从「打字输入 → 静态计划表」改成「拍照 → 说话 → 确认 → 汇报 → 群通知」的
> 全模态协作闭环，4–6 分钟讲完。与 [比赛Demo演示流程.md](./比赛Demo演示流程.md) 的六步文字版互补：
> 本脚本是昇腾评审版主脚本，六步文字版作为降级/补充素材。

## 1. 核心主张（开场 30 秒话术）

> 普通工具只在项目开始时生成一张计划表；我们的系统让 MiniCPM-o 的
> **听、说、看**能力直接进入协作流程——拍照就能立项、说话就能排期、
> 汇报页用语音/照片更新任务、状态变化自动通知群。

## 2. 演示前准备（清单）

- [ ] 跑 `python scripts/preflight_demo.py`，确认应用、A3/云端后端、Realtime 状态、暖机对话全部通过
- [ ] 准备一张「需求素材」：白板照片 / 课程要求截图 / 群聊通知截图（带字，方便视觉理解展示）
- [ ] 准备一段「组会讨论录像」（≤3 分钟、≤60MB，画面有 PPT/白板/文档，人声清晰）
- [ ] 演示环境 `.env`：`ASCEND_OMNI_WS_URL` 已取消注释（昇腾录屏）或保持云端（纯 API 演示）
- [ ] 汇报链接：可现场生成，无需预建；`APP_NOTIFY_WEBHOOK` 若未配置，用「发送提醒通知」替代真实推送
- [ ] 清空 `memory/` 中无关旧方案，只保留一份备用结果
- [ ] 手机与演示机在同一网络，用于现场打开成员汇报链接

## 3. 五步演示脚本（建议 4–6 分钟）

### 第一步：拍照 → 需求直接进拆解（约 60 秒）

操作：

1. 打开项目配置页，点「📷 拍照需求」：桌面弹取景框、手机用后置摄像头；
   对着白板/需求截图拍一张（或直接选图）。
2. 照片进入文件列表，状态显示「已读取」，摘要展示为 `[图片理解]`（文字 + 非文字内容，
   如流程图、界面、手绘）。
3. 点「AI 生成任务拆解」，草案基于照片内容生成。

讲解词：

> 需求不用打字：拍一张白板或群聊截图，MiniCPM-o 先看明白画面里写了什么、
> 画了什么，再参与任务拆解。无文字的流程图也能理解，不只是 OCR。

预期结果：文件列表出现照片且状态为「已读取」；背景区能看到图片理解摘要；
拆解草案已生成。

### 第二步：说话 / 录像 → 边看边听补全任务（约 90 秒）

两种讲法任选其一（推荐「会议旁听录像」，最能展示全模态差异点）：

**讲法 A：组会录像边看边听（重点）**

1. 点「🎙 会议旁听」，选择一段组会录像（mp4/mov/webm）。
2. 等待 1–3 分钟：系统抽帧看画面（PPT/白板/文档）+ 抽音频听人声，
   弹窗同时给出「会议要点」「任务（负责人/截止）」「风险/待确认」和
   「📹 视频画面理解」。
3. 点「生成任务草案」：要点、任务与画面理解自动填入项目背景，进入拆解。

**讲法 B：语音补充需求**

1. 点「🎤 添加语音需求」，说「我们三个人五天完成调研报告，张三负责数据收集」。
2. 录音作为需求材料进入文件列表（不贴文本），状态「已读取」。

讲解词：

> 开会录一段视频，系统既听声音里的分工，又看画面里的排期表和 PPT，
> 边看边听地把会议变成可执行的任务草案。这是 MiniCPM-o 最独特的能力：
> 同一个输入里同时理解视频、音频和视觉内容。

预期结果：会议弹窗出现结构化要点/任务/风险 + 每帧画面理解；点击生成后
背景文本包含「【会议旁听整理】」与「画面理解」，草案可编辑。

### 第三步：确认 → 分工与排期（约 60 秒）

操作：

1. 在拆解页快速浏览任务，现场改一处（例如把某项工时 +1h），强调人机协同。
2. 点「确认拆解并开始分工」→ 成员看板展示技能匹配与负载均衡。
3. 点「确认最终分工」→ 打开甘特图，指出红色关键路径、黄色缓冲。

讲解词：

> AI 负责建议，人负责判断；改一个工时，排期与分工自动重算。

### 第四步：执行汇报 → 语音/拍照交付（约 60 秒）

操作：

1. 顶栏「成员汇报链接」→ 选一名成员 → 生成专属链接。
2. 用手机（或新窗口）打开链接，进入轻量汇报页，无需登录。
3. 点任务上的「🎤 语音汇报」，说「完成了，实际做了 6 小时」→ 确认应用；
   或点「📷 拍照交付」上传交付物照片。

讲解词：

> 成员不用学工作台：一个链接、一条语音、一张照片就能汇报。
> 系统听懂「状态 / 工时 / 备注」，确认后自动更新方案并重算排期。

预期结果：任务状态变更为「已完成」、实际工时写入、方案自动重算；
拍照交付的备注出现「交付物照片已上传」。

### 第五步：群通知 → 协作触达（约 30 秒）

操作：

1. 配置 `APP_NOTIFY_WEBHOOK`（企业微信群机器人 URL）后，汇报页状态变更
   自动推送「张三 已完成「调研」（实际 6h）」。
2. 若现场未配置 webhook，改用提醒页「发送提醒通知」演示推送能力。

讲解词：

> 状态变化不只停留在页面里，而是自动触达团队群；负责人不用反复追问进度。

## 4. 时间预算

| 步骤 | 内容 | 预算 |
|---|---|---|
| 开场 | 核心主张一句话 | 30s |
| 1 | 拍照需求 → 拆解 | 60s |
| 2 | 会议录像边看边听 / 语音需求 | 90s |
| 3 | 确认拆解 → 分工 → 甘特 | 60s |
| 4 | 汇报链接 → 语音/照片汇报 | 60s |
| 5 | 群通知 | 30s |

总时长约 5.5 分钟；超时优先砍第二步讲法 B 与第五步细节。

## 5. 演示红线（必守）

- 本地昇腾后端绝不打开「语音回复 / 播报」：910C TTS 会挂起单会话服务；
  TTS 只走云端。前端已自动禁用，现场别手动开。
- 不演示「你是谁 / 基于什么模型」；不演示高难度数学/推理（8B 弱项）。
- 兜底模型配置（`APP_VISION_*` / `APP_ASR_*`）保持注释，昇腾故障必须可见。
- 视频理解等待 1–3 分钟属正常，提前告知评审「边看边听需要一点时间」。
- 演示机先跑 `preflight_demo.py` 暖机，避免 A3 空闲失联。

## 6. 异常兜底

| 异常 | 处理 |
|---|---|
| 摄像头打不开 | 自动回退文件选择，选预存截图继续 |
| 视频理解超时/失败 | 改讲「录音会议旁听」或「语音需求」；弹窗展示 warning 说明 |
| 云端 API 不可用 | 切 A3；或退回六步文字版 [比赛Demo演示流程.md](./比赛Demo演示流程.md) |
| 群机器人未配置 | 展示提醒页「发送提醒通知」 |
| 时间不够 | 砍第二步讲法 B 与第五步，保留拍照→确认→汇报主链路 |

- [ ] 语音需求：录音进文件列表，不贴背景文本
- [ ] 确认拆解 → 分工 → 甘特图关键路径清晰

- [ ] 状态变更自动推送 webhook（或提醒通知可演示）
- [ ] 全程无横向溢出、无卡死；控制台无报错
