# 课程作业 MVP 拆解方案 v2（完整梳理 + 协作图动态修改）

> 背景：比赛选题 = 清华小组合作智能体。同一选题用作**个人课程大作业**，时间紧，先做完一部分，其余比赛阶段扩展。
> 策略：**纵切深井**——作业 = 一条可运行的多 Agent 主链路 + 几个低成本高差异点；比赛 = 在外延补 RAG / 前端增强 / 部署 / 比赛材料。

## 1. A 类（必做，跑不通就无法演示）
| 编号 | 项 | 来源模块 | 说明 |
|------|---|:--------:|------|
| A1 | LLM 调用封装 + Structured Output | ④ | 一切 Agent 的基础 |
| A2 | Coordinator→Planner→Matcher→Timeline→Report 主链路 | ⑤ | 必须端到端跑通 |
| A3 | QA 责任矩阵生成 | ⑤(Matcher 扩展) | 核心差异化（文档已标"护城河"） |
| A4 | 倒排时间线 + 关键路径标红 | ⑤(Timeline) | 强可视化，也是功能 |
| A5 | FastAPI + 简易 Web（**先只读渲染**） | ⑧⑨ | Demo 载体；编辑 UI 留到 B4 |

**依赖修正（重要）**：A3 的 QA 矩阵需要"答辩细分 + 谁主讲/谁主答"。把**最小版**答辩细分 + 主讲/QA主答识别拉进 A 类（仅够驱动矩阵）；更重的角色能力匹配（表达/应变标签、轮值制）留在 B3。否则 A3 在作业里会"半成品"。

**可解释性（建议并入 A2/A3，零成本）**：每个匹配附一句"为什么张三主答第 3 章"——既是卖点，也是答辩话术。

## 2. B 类（加做，拉开差距）
| 编号 | 项 | 来源模块 | 说明 |
|------|---|:--------:|------|
| B1 | 答辩模拟 Agent（轻量） | ⑤ | 生成 10~15 道可能问题并演示 |
| B2 | Memory（最小版） | ⑭ | 仅"保存/加载计划 JSON"即可，支撑 B4；**勿过度承诺** |
| B3 | 答辩细分 + 角色能力匹配（完整版） | 第二层 | 表达/应变标签、轮值制 |
| B4 | 协作图 + 动态修改 | 新增 | 见下，作为**最后一个 B 项**，以 A 类稳固为前提 |

### B4 设计要点：协作图 = "计划即状态"
- **核心洞察**：把"计划"当作**可变的活对象**（JSON / DAG），而非一次性文本。任务为节点、依赖为边、人员与 QA 归属为节点属性。
- **实现取巧**：定义少量受控 mutation 操作（`add_task` / `remove_task` / `reassign` / `change_ddl`），每个操作在修改后的 JSON 上**重跑** Planner/Timeline/Matcher——复用主链路，不另起炉灶。
- **演示剧本（务必彩排）**：① 组员退出 → 看重匹配；② DDL 提前 → 看关键路径标红变化。
- **风险收敛**：编辑面只做这 4 类；依赖改动做**环检测**；重算用"全量重跑"即可，不必做增量。
- **与 A5/B2 耦合**：编辑 UI 仅在做 B4 时补；B2 的"保存计划状态"直接给 B4 当持久层。

## 4. 一句话叙事（答辩用）
> 别人给你一张**静态分工表**；我们给你一张**可编辑的活协作图**，并且每个任务都带**角色化的 QA 归属**——计划会随现实变化而重算。

## 5. 推荐节奏
- **本周**：A1 + A2 跑通"Hello World → 返回任务拆解"。
- **下周**：A3 + A4 + A5(只读) 补齐，做成可演示 MVP。
- **有余力**：B1 → B3 → B2 → B4（顺序，B4 最后）。
- **比赛阶段**：在链路上加 C 类。

## 6. 5 天可行性 & 提交范围（2026-07-11 补充）
- 距提交仅 5 天。"AI 写代码、人做架构"成立，但前提：AI 只接**管道/样板**（LLM 封装、Agent 骨架、FastAPI、只读 Web、utils）；**人必须亲自做**三件事——① 数据模型与 JSON Schema 定死 ② Prompt 撰写与迭代 ③ 每日亲自跑通验证 + 演示彩排。
- 真实瓶颈不是"写代码"，是：Prompt 迭代（比预期慢 2-3 倍）、Agent 间 JSON 接缝联调、现场演示可靠性（API 限流/超时/Key）。
- **提交范围建议**：A 类全做 + B1（答辩模拟，纯 Prompt 便宜）最多加一个；B4（协作图动态修改）列为"有空才做，落后即砍"。
- **最大风险**：Day5 才发现主链路从未真正端到端跑通。对策：Day1 就先跑通最小垂直切片（哪怕 Planner 先用较糙的 prompt），再逐步打磨，禁止孤立完美化单个 Agent。
- 每日亲自运行验证，不接受"AI 说写好了"。

### 5 天日程（单人/小队，AI 接管道）
- **D1** 数据模型 + JSON Schema 定死 + LLM 封装(A1) + FastAPI 骨架 + HelloWorld + 最小垂直切片跑通（输入→Planner→任务列表）。
- **D2** Planner + Matcher prompt + 主链路(A2) 跑通；重 Prompt 迭代。
- **D3** Timeline(A4) + QA 矩阵(A3，含最小答辩细分+主讲/QA主答) + 可解释性。
- **D4** 只读 Web(A5) + B1 答辩模拟 + 边界用例(1人/10人/DDL 1天/不会Python)测试。
- **D5** 联调 + 演示彩排 + 收尾（buffer：落后则砍 B1/B4）。

## 7. 三人分工（课程作业版，用户 = B 软件工程）
**模型**：作业是你的（你交、你评分），但三人都想练手。所以你扛**脊梁 + 总集成（占大头）**，A / C 各端到端认领一个**完整 Agent**（练 设计→代码→测试），你拼进主干后以自己的作业提交。评分看的是你集成出的成果。

| 人 | 角色底色 | 端到端负责（设计→代码→测试） | 占提交比重 |
|---|---|---|---|
| **你（B，提交人）** | 软件工程 | 骨架 + LLM 封装(A1) + FastAPI/只读 Web(A5) + Coordinator 总调度 + 主链路接线 + 集成/联调/彩排 + 兼 B1 答辩模拟 + B2 Memory 最小版 | 最大块（≈50%+，总负责） |
| **队友 A（Agent 设计）** | AI 架构/Agent 设计 | 端到端负责 **Planner Agent**：输入课程/要求/组员 → 输出 5-8 子任务（工时/依赖）JSON | ≈25% |
| **队友 C（知识增强→效果优化）** | 知识增强 | 端到端负责 **Timeline + QA 责任矩阵**（A4+A3）：倒排/关键路径 + 责任矩阵 + 可解释性 + Report 格式化 | ≈25% |

**第 0 步（你作为提交人必须先做）**：定死三个 Agent 的 **JSON 接口契约**（输入字段 / 输出字段 / 错误格式），再让 A / C 并行开写。契约不定，集成必炸——这正是你"人做架构"里最值钱的部分，也是 D1 该干的事。

**B 类分配（灵活）**：
- B1 答辩模拟 → 你（B）做（纯 prompt，演示最闪）
- B3 角色匹配完整版 → 归 C（在 QA/匹配域内）
- B2 Memory 最小版 → 你（B）做（保存/加载计划 JSON，兼 B4 持久层）
- B4 协作图动态 → 有空才做、落后即砍；若做，你（B）主导（编辑 UI + mutation 重跑）

**学习保障**：沿用你们文档的"复盘课"——每人交付后给另外两人讲 30~60 分钟（A 讲 Planner 设计、C 讲 Timeline/QA、你讲骨架与集成），确保三人都获得完整搭建体验，不止会用能讲清。
