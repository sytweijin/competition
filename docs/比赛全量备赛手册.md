## 3. 项目现状

项目定位：把项目要求、成员能力、截止日期转化为可编辑的任务拆解、分工、排期和报告，并在此基础上叠加 MiniCPM-o 全模态交互。

已接入能力：

- 文本对话：`POST /api/realtime/chat`
- 图片理解：上传图片 / 扫描 PDF 自动走 MiniCPM-o Realtime（文字 + 图表/界面/场景等非文字内容）
- 音频转写：上传 mp3/wav/m4a/webm 自动走 MiniCPM-o Realtime
- TTS：接口已支持返回音频 Base64，前端播放未完成
- 本地昇腾后端：配置 `ASCEND_OMNI_WS_URL` 后，对话直接走 A3 的 `llama-omni-server /backend`

关键文件：

## 4. 技术架构与配置

### 4.1 两种后端

| 后端 | 配置 | 说明 |
|------|------|------|
| `map` | `MAP_REALTIME_API_KEY=...` | ModelBest 云端 Realtime API，免费，开发期兜底 |
| `local` | `ASCEND_OMNI_WS_URL=ws://127.0.0.1:28099/backend` | 昇腾 A3 本地 llama-omni-server，评审期主力 |

`/api/realtime/status` 返回 `backend: "local" | "map"`，可直观确认当前链路。

### 4.2 环境变量

```dotenv
MAP_REALTIME_API_KEY=你的Key
MAP_REALTIME_MODEL=MiniCPM-o-4.5-Realtime
MAP_REALTIME_BASE_URL=wss://api.modelbest.cn/v1/realtime
MAP_REALTIME_MAX_TOKENS=1024
MAP_REALTIME_TIMEOUT=60

ASCEND_OMNI_WS_URL=ws://127.0.0.1:28099/backend
ASCEND_OMNI_TIMEOUT=300
```

`MAP_REALTIME_API_KEY` 只放 `.env`，绝不提交 Git。

### 4.3 本地开发流程

本地跑应用：

```bash
python -m app.main
```

检查后端：

```bash
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/realtime/status
```

测试对话：

```powershell
$body = @{ message = "你好" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/realtime/chat" -Method Post -ContentType "application/json" -Body $body
```

### 4.4 昇腾端口转发

本地应用要连 A3，需要在 VSCode Remote-SSH 的 Ports 面板把 A3 的 `28099` 转发到本地。关掉转发或 A3 关机，本地 `local` 链路会失败；纯业务开发时可临时注释 `ASCEND_OMNI_WS_URL` 切回云端 API。

## 5. 昇腾部署进度

已完成：

- A3 环境：CANN 9.1.0-beta.1、Ascend 910C、Python 3.12.13
- 模型：`/workspace/MiniCPM-o-4_5-gguf/` 10 个 GGUF 文件已下载，F16 主模型约 16G
- 源码：`llama.cpp-omni` 已 clone（国内走 `ghfast.top` / `gh-proxy.com` 等代理）
- 编译：`-DGGML_CANN=ON -DLLAMA_OPENSSL=OFF` 成功，含 `llama-omni-server` / `llama-omni-cli`
- 服务：`llama-omni-server` 监听 `0.0.0.0:28099`，`/health` 返回 `{"engine":"comni","status":"ok"}`
- 验证：文本 7.94 秒出回复；音频 2.86 秒理解并回答

关键命令（A3 上）：

```bash
cd /workspace/llama.cpp-omni
nohup ./ascend_start_server.sh > /tmp/llama-omni-server.log 2>&1 &
curl http://127.0.0.1:28099/health
```

已知风险：

- A3 资源紧张，关机后可能很难再开；多卡环境卡时翻倍
- 910C + llama.cpp-omni 的 TTS 有已知 `aclnn_repeat_interleave` 算子报错；官方分支应可用，报错找官方
- `vision_backend` 默认 `metal`，Linux/昇腾上视觉输入仍需适配
- `llama-omni-server` 只支持一个活跃 session，WebSocket 与 HTTP 不要混用
- 客户端必须用 `websocket-client`，不要用 `websockets`（keepalive ping 会超时）

## 6. 群聊经验（已归档）

原始记录：

- `docs/群聊记录/2026-08-04_至_08-14_群聊记录.md`
- `docs/群聊记录/2026-08-15_至_08-20_群聊记录.md`
- `docs/群聊记录/README.md`

核心结论：

1. 创新应用赛道指定 `llama.cpp-omni`；`vLLM-Omni` 是推理优化赛道子赛道 B
2. 昇腾镜像选 CANN；910C 上 F16 最快，Q4_K_M 会退 CPU
3. A3 难抢、关机后难开；卡时不足可申请补充
4. SSH 不稳时优先 WebIDE；频繁 SSH 重连可能被封 IP（418）
5. TTS 有已知算子问题，官方分支应可用
6. 视觉后端 Linux/昇腾未完全适配
7. 官方免费 API 和本地部署官方都接受
8. 截止 8 月 31 日
9. Demo 公网访问：WebIDE 端口转发会随关闭失效；Dev Tunnel / SSH 隧道 / VPS 可常驻
10. MiniCPM-o 4.5 是 8B 模型，数学/强推理弱，演示避开高难度解题

## 9. 风险与兜底

| 风险 | 兜底 |
|------|------|
| A3 关机/排队拿不到 | 开发期用 MAP API 继续开发；最终用 API 录 Demo 并如实标注 |
| 910C TTS 算子报错 | 联系官方；演示一律用云端 API 做 TTS；本地后端严禁开 TTS（会挂起单会话服务、health 无响应，需重启 llama-omni-server） |
| 视觉后端昇腾不可用 | 先用 API 演示视频；后续适配 llama-omni vision |
| 端口转发失效 | 用 VSCode Ports / Dev Tunnel / SSH 隧道 / VPS |
| 磁盘被平台回收 | 优先用 `/workspace/shared_assets` 共享模型，别重复下载 |
| 卡时不足 | 申请补充；不用时关机；多卡环境注意倍率 |
