## 四、已修复缺陷（本轮）

### 1. [P0] 合规模式下"答辩模拟-生成问题"必然失败

- 现象：`APP_MODEL_MODE=minicpm` 时 `LLMClient.chat_text` 的 `self._client` 为
  `None`，`/api/interview` 直接 `AttributeError`，前端把错误文本当第一个问题展示。
- 修复：`chat_text` 增加 minicpm 分支，与 `chat_messages` 一致走
  `_realtime_text`（本地 A3 / 云端）。
- 验证：新增 `test_chat_text_minicpm_routes_to_realtime`；全量测试通过。

### 2. [P1] 答辩录像"回答转写"二次解码必然失败

- 现象：`realtime_performance` 把 `extract_audio_pcm16k` 已解码的 PCM 再次传给
  `audio_to_written_answer`（内部再次 `av.open` 解码），实测必抛
  `InvalidDataError`，`answer` 恒为空。
- 修复：改为传入原始上传字节 `raw`。
- 验证：新增 `test_realtime_performance_passes_raw_file_to_written_answer`。

### 3. [P1] 转写接口乱码泄露 + 文件分析转写污染

- 现象：`/realtime/transcribe` 只拦客套回复，不拦 "?" 乱码；
  `_realtime_audio_transcribe_text` 逐片转写会把乱码/客套片拼进结果。
- 修复：转写路由增加 `_looks_like_garbage` 校验（命中 502）；
  文件分析转写逐片过滤乱码/客套，全无效时抛明确错误。
- 验证：新增 `test_realtime_transcribe_garbage_returns_502`。

### 4. [P1] 答辩/会议音频失败时放弃已有画面 + 表现观察提示词跑偏

- 现象：音频理解失败（A3 未听懂/超时）时，即使录像抽帧成功也整体 502；
  `PERFORMANCE_PROMPT` 约束不足，模型描述照片画面而非点评答辩者神情。
- 修复：答辩回合音频失败→帧观察兜底（无帧才 502，保留原始错误信息）；
  会议音频失败且有画面→仅凭画面整理；会议帧观察丢弃乱码帧；
  表现观察提示词明确"只针对神情/眼神/姿态，禁止描述画面内容"。
- 验证：新增 `test_interview_turn_audio_failure_falls_back_to_frames`、
  `test_meeting_audio_failure_falls_back_to_visual`。

### 5. [P3] 元数据

- `app/main.py` FastAPI `version` 由过期 `5.76` 对齐为 `7.1`。

### 6. [P0] 抽屉对话被"客套守卫"误判为模型不可用（2026-08-24 追加）

- 现象：AI 抽屉文字对话显示"当前模型服务不可用，但我已读取到当前任务草案：
  共 0 项、预计 0 小时"。
- 根因：模型对"你好"的正常回复"你好！有什么问题我可以帮您解答吗？"被
  `_looks_like_canned_reply` 的"你好开头 + 含帮/请问/需要"规则误判为客套异常，
  `/api/realtime/chat` 502 → 前端切兜底 → `/api/chat` 同一守卫再次失败 → 兜底文案。
- 修复：① 客套判定细化（问候开头的完整疑问句"吗/么"结尾不算客套）；
  ② 抽屉文字对话只拦乱码、不再拦客套；③ 抽屉语音对话经 `understand_audio`
  `allow_polite=True` 跳过客套判定（转写/会议/答辩仍严格）；
  ④ 兜底文案在无方案时提示"请先生成任务草案"。
- 验证：实测 `/api/realtime/chat` 与 `/api/chat` 均 200 正常回复；
  全量测试 339 → 341 passed（新增 3 个回归用例）。

### 7. [P0] 本地语音对话无记忆：三段式重做（2026-08-24 追加）

- 现象：语音对话告诉模型"我叫小红"，再语音问"我叫什么名字"，模型答
  "我叫助手/不知道"。
- 根因（实测定位）：① 本地 A3 把"转写指令"当对话回应（"你好，小红！很高兴
  认识你"），4 种转写提示词全部失败 → transcript 空 → 历史只剩占位符；
  ② 直接听音频回答时模型忽略文本历史、对"我叫什么名字"自我指代混乱；
  ③ 转写偶尔编造名字（"我叫小明/通义千问"）污染记忆。
- 修复：本地语音对话改三段式（`prefer_text_answer=True`）：
  宽松转写（过滤模型自我介绍）→ 纯文本回答（历史+记忆放 system prompt，
  指代纠正提示）→ 记忆抽取（"用户的名字是：X"返回 `memory` 字段，前端写入
  历史）。另有记忆冲突保护：转写名字与既有记忆矛盾时丢弃并沿用旧记忆。
- 验证：端到端实测"我叫小红→我叫什么名字"回答"你的名字是：小红"，
  记忆跨轮持续；全量测试 341 → 344 passed（新增 4 个回归用例）。

## 五、已验证的重点链路（本轮未发现新问题）

- 长会议分片：≤12 秒静音断句 + ≤3 片分层合并 + 劣化分片过滤，3.4 分钟会议约 2 分钟出纪要。
- 语音记忆：本地/云端均把多轮历史摊平（`_flatten_history`），跳过 `[语音消息]` 占位；
  本地语音回合后端补一次转写校验后写入 `transcript`。
- 问号守卫：转写/口述/会议/答辩/语音对话全覆盖，绝不把 "?" 串展示给用户；
  抽屉文字乱码重试后仍失败给友好提示。
- 合规化：minicpm 模式下不创建 DeepSeek/DashScope 客户端，`/api/chat`、
  `/api/interview`、`/api/interview/chat`、图片理解、音频理解全部走 MiniCPM-o。
- 文件解析（PPTX/PDF/Word/TXT/图片/音频）与"会议→生成任务草案"闭环。
- 健康检查按模式判定；`/api/ready` 的 S3 严格检查为预期行为（本地 local 存储返回 503）。

## 六、剩余风险与建议

1. **A3 音频识别不稳**：多次问号/空转是模型侧问题，演示时若关键功能
   （答辩语音、会议旁听）连失败，可临时注释 `.env` 中 `ASCEND_OMNI_WS_URL`
   切云端 ModelBest 演示（云端功能稳定）。

   需要入口，可在答辩面板补一个"上传录像"按钮接该接口（当前演示走
   `interview-turn` 的视频回答 + 内嵌表现观察）。
3. **SSH 保活**：VSCode Remote-SSH 偶发断连，可在 `~/.ssh/config` 加
   `ServerAliveInterval` / `ControlMaster` 参数；本轮未改用户 SSH 配置。
4. **上游根治**：`llama.cpp-omni` 的多帧视觉退化与音频识别不稳需上游 C++ 修复，
   建议赛后跟进 `tc-mb/llama.cpp-omni` master，不在赛前冒险。
5. **比赛材料**（PPT/演示视频/压测记录/用户手册）另开对话桌处理；
