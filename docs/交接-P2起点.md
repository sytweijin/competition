### 通用修复（重要教训）
- **云端音频理解差异**：云端 MAP Realtime 的 turn-based chat 对音频输入=“转写并复述”，
  本地 A3 能直接听。统一入口 `app/services/omni_chat.py`：本地直接听，
  云端先转写再文字理解。**新增任何音频理解接口必须走 `understand_audio`**，不要裸调 RealtimeClient 发音频。
- 答辩/会议/语音汇报提示词**禁用尖括号占位符**（模型会照抄输出）
- 8B 模型身份：提示词约束为"协作分工助手"，问"你是谁"不会暴露底层模型

## 4. 关键架构决策（新对话别推翻）

- **omni_chat 适配层**：本地直接听音频；云端先转写再理解（见上）
- **汇报页 token**：`app/services/report_link.py`，令牌存 `memory/report_tokens.json`，
  备注存 `memory/report_notes.json`；附件存 `memory/attachments/`
- **负责人确认制（v7.0 增强）**：协作者可报"我的部分完成/阻塞"（成员级状态，
  任务级状态不变并标记"等待负责人确认"）；负责人汇报页可看到每个协作者的状态/
  工时/交付物/备注，确认后任务才完成；照片非负责人记为"等待负责人确认"
- **工时累加**：任务实际总工时 = 各成员"最近一次带工时的上报"之和（3h+3h=6h）；
  语音提示词明确只报个人工时，不报团队总工时；**纯状态变更（无工时）会清除该成员
  此前工时**——改回未完成即退出累计
- **任务完成不变量**：任务 completed ⟺ 所有成员自己的部分均 completed 且负责人确认；
  协作者把已完成改回 未开始/进行中/阻塞 时任务自动回退"进行中"并通知负责人；
  协作者可正常报阻塞（成员级记录）
- **双向自动同步**：汇报页状态下拉即自动保存；主页面/汇报页在焦点回来时自动
  从磁盘刷新（有未保存修改时主页面先确认再覆盖）
- **交付物照片**：存 `memory/attachments/`，`GET /api/report/attachment` 鉴权查看；
  负责人可看全部、协作者/志愿者看自己的
- **大型项目**：已确认志愿者（`volunteer_pool` status=已确认）可生成汇报链接并汇报，
  角色显示"志愿者"，由模块负责人（骨干）确认完成；**负责人可代成员确认**：
  `report/update` 传 `member` 字段写入 `confirmed` 状态（行内"已确认"徽标、工时保留）
- **团队总览（v7.0）**：大型项目中角色为"项目负责人"或担任某成员"上级"的成员，
  交付页顶部显示只读"团队总览"（项目进度/工时 + 按模块分组任务与成员进度/交付物）；
  确认动作仍在模块负责人"我的任务"里。**入口**：主页面「成员汇报链接」→ 选择
  带「★ 团队总览」的项目负责人（方案需有该角色成员，或在骨干管理里给骨干填"上级姓名"）
- **版本号管理**（AGENTS.md 已写）：小修复/命名/配置不升版本，并入当前版本 CHANGELOG；
  只有功能里程碑才升版本；静态资源参数用内容哈希
- **前端 JS 强制规则**（AGENTS.md）：改 `index.html` 后必须 node --check 两个 JS、
  字符串拼接排查、Unicode 转义排查、`python -m pytest tests/ -q`（当前 291）

## 5. 红线与已知坑

- **910C 本地 TTS 会挂单会话服务**：本地后端绝不开启语音回复/播报（前端已自动禁用）；
  `/api/realtime/tts` 在本地后端直接返回 501，不碰模型
- **A3 空闲失联**：演示前跑 `python scripts/preflight_demo.py`（含暖机对话）；
  失联重启：`pkill -f llama-omni-server && nohup ./ascend_start_server.sh &` 后 curl health
- 演示/录屏用 **A3（昇腾复现）**；开发验证用云端
- 不演示"你是谁/基于什么模型"；不演示高难度推理（8B 弱）
- `competition` 基础版不随昇腾副本改动，除非用户明确要求同步
