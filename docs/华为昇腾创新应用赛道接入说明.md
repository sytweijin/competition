# 华为昇腾创新应用赛道接入说明

## 1. 定位

本副本面向华为昇腾创新应用赛道，主路线使用 MiniCPM-o 4.5 全模态模型：

- 模型权重：完整 `MiniCPM-o-4_5-F16.gguf`
- 推理框架：`llama.cpp-omni`
- 镜像环境：CANN 9.1.0-beta.1
- 前端/后端通信：统一走 WebSocket `/backend`

创新应用赛道不把 `vLLM-Omni` 作为主路线；`vLLM-Omni` 属于推理优化赛道的方案，避免在两套部署方式之间混用。

## 2. 为什么先接 API

A3 环境资源紧张、自动开机不成功时，Demo 开发不能一直等待算力。ModelBest 提供免费 Realtime API，可以先用云端模型把对话链路跑通；A3 环境可用后再切回本地 `llama.cpp-omni`，接口层尽量保持不变。

同一个 API key 下还列出了 `MiniCPM-V-4.5`、`MiniCPM-V-4.6` 等视觉模型，但昇腾赛要用的主模型只有 `MiniCPM-o-4.5-Realtime`，代码里也已固定为这个模型。当前版本的图片 OCR、扫描 PDF、音频转写都会优先走 MiniCPM-o Realtime；旧版 `APP_VISION_MODEL` / `APP_ASR_MODEL` 只保留为回退路径。昇腾赛演示只需要填 `MAP_REALTIME_API_KEY`。

## 3. 环境变量

在 `.env` 中配置：

```dotenv
MAP_REALTIME_API_KEY=你的ModelBest_API_Key
MAP_REALTIME_MODEL=MiniCPM-o-4.5-Realtime
MAP_REALTIME_BASE_URL=wss://api.modelbest.cn/v1/realtime
MAP_REALTIME_MAX_TOKENS=1024
MAP_REALTIME_TIMEOUT=60
```

## 4. 新增接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/realtime/status` | 查看 Realtime 是否配置成功、当前模型 |
| POST | `/api/realtime/chat` | 调用 MiniCPM-o Realtime Chat 模式 |
| POST | `/api/realtime/transcribe` | 录音文件转写：优先 MiniCPM-o Realtime，未配置时回退 ASR 模型 |
| POST | `/api/realtime/voice-chat` | 直接语音对话：录音作为音频消息发给 MiniCPM-o，返回文本回答与可选语音（表单参数 `tts_enabled`、`system_prompt`，后者可带方案快照上下文；回答强制"不复述用户原话"） |
| POST | `/api/realtime/meeting` | 会议旁听：**录音/录像皆可**。录像自动抽 3 帧做画面理解 + 抽音频整理 要点/任务/风险；无声轨录屏仅凭画面合成结构化结果。返回 `summary/tasks/risks/visual/has_video/raw` |
| POST | `/api/realtime/interview-turn` | 答辩直接语音/视频对话：评委听（看）后输出 回答摘要 + 评委回复（点评/追问），视频附逐帧表现观察 |

请求示例：

```json
{
  "messages": [
    {"role": "system", "content": "你是项目协作助手，回答简洁自然。"},
    {"role": "user", "content": "帮我看看这个任务安排合不合理？"}
  ],
  "max_new_tokens": 1024,
  "tts_enabled": false
}
```

也可以只传 `message`：

```json
{"message": "你好，介绍一下你自己"}
```

## 5. 本地验证

启动服务：

```bash
python -m app.main
```

检查配置状态：

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/realtime/status
```

测试对话：

```powershell
$body = @{ message = "你好" } | ConvertTo-Json
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/realtime/chat `
  -Method Post -ContentType "application/json" -Body $body
```

## 6. 协议要点

服务端客户端连接：

```text
wss://api.modelbest.cn/v1/realtime?mode=chat&model=MiniCPM-o-4.5-Realtime
Authorization: Bearer MAP_REALTIME_API_KEY
```

事件顺序：

```text
<- session.queue_done
-> session.init
<- session.created
-> input.append
<- response.output.delta（text / audio）
<- response.done
-> session.close
```

客户端同时兼容平台控制台文档中的 `response.output_text.delta` / `response.output_audio.delta` 事件别名，避免两份文档事件命名不一致导致回复丢失。

图片输入使用 `{"type": "image", "data": "<base64 image>"}`；音频输入先由 PyAV 解码为 16kHz 单声道 float32 PCM，再使用 `{"type": "audio", "data": "<base64 PCM>"}` 并开启 `omni_mode: true`。

**图片理解 / 音频转写兜底链路**（三级）：MiniCPM-o Realtime（本地昇腾或云端）→ `APP_VISION_*` / `APP_ASR_*` 通用模型（当前为阿里 DashScope `qwen3.7-plus` / `qwen-audio-3.0-asr-flash`）→ 仅保留文件元数据并提示“需要确认”。图片理解不止提取文字，还会描述图表、流程图、界面、场景等非文字内容并转化为需求材料；MiniCPM-o 全部不可用时，文件分析仍能输出真实图片理解 / 转写文本。

> **当前状态：兜底配置默认注释。** 评审/联调期保持注释，让昇腾或云端 MiniCPM-o 的故障直接可见（文件显示"需要确认"），避免被兜底模型静默掩盖；需要启用时取消 `.env` 中 `APP_VISION_*` / `APP_ASR_*` 的注释并重启。

**语音输出（TTS）**：官方 Realtime 协议返回的 `audio` 是 24kHz 单声道 float32 PCM（base64），浏览器不能直接播放。后端会在 `tts_enabled=true` 时自动把 PCM 转成 16bit WAV，随响应返回 `audio_wav_base64`，前端用 `new Audio('data:audio/wav;base64,...')` 直接播放即可。语音回复开关与重听按钮已在工作台 AI 建议抽屉内置。

**注意：TTS 仅云端后端（`backend: "map"`）演示可用。** 本地 llama-omni-server（910C）存在已知 TTS 算子问题，开 TTS 会让单会话服务挂起、health 不再响应，需要重启服务；前端语音开关在本地后端下会自动禁用。TTS 失败时后端会自动降级为纯文本重试并返回 `tts_failed: true`，对话不中断。

**音频理解差异（云端 vs 本地）**：本地 llama-omni-server 能直接"听"音频并回答；云端 MAP Realtime 的 turn-based chat 对音频输入表现为"转写并复述"。统一入口 `app/services/omni_chat.py` 自动分流：本地直接听，云端先转写再文字理解。语音对话、答辩、会议旁听、语音汇报四个接口均走该入口，两端行为一致。

客户端实现见 `app/services/realtime_client.py`，只发送 JSON 文本帧；音频输入输出使用 Base64 编码，不混用 HTTP 接口。

## 7. 本地 llama-omni-server 接入（昇腾 A3）

昇腾 A3 上 `llama-omni-server` 启动后，监听 `0.0.0.0:28099`，WebSocket 路径为 `/backend`。项目支持通过环境变量一键切换：

```dotenv
# 本地昇腾后端；配置后优先走本地，MAP_REALTIME_API_KEY 可留空
ASCEND_OMNI_WS_URL=ws://127.0.0.1:28099/backend
ASCEND_OMNI_TIMEOUT=300
```

如果应用运行在本地电脑，需要在 VSCode Remote-SSH 的 Ports 面板把 A3 的 `28099` 转发到本地，再填上面的地址。

本地协议差异：

| 项目 | 云端 MAP Realtime | 本地 llama-omni-server |
|------|-------------------|------------------------|
| 鉴权 | Bearer API Key | 无 |
| 等待事件 | `session.queue_done` | 无需等待 |
| `session.init` | `payload: {}` | `payload: {"mode": "turn_based", "use_tts": false}` |
| 输入帧 | 含 `tts/enable_thinking/omni_mode` | 仅 `messages/streaming/generation` |
| 结束 | 发送 `session.close` | 直接关闭连接 |

验证接口：

```bash
curl http://127.0.0.1:8000/api/realtime/status
```

配置本地后端时返回 `backend: "local"`；未配置时返回 `backend: "map"`。
