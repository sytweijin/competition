# 小组合作智能体

**版本：v4.8** | 最后更新：2026-07-22（v4.7.1 算法修复 + v4.7.2 工时知识库统一合并）

## v4.8 统一合并：算法修复 + 工时知识库

将 v4.7.1（v3.5-v3.8 算法修复）与 v4.7.2（知识库增强工时估算）两条独立发展线合并到同一代码基础，保留双方全部功能。

## v4.7.1 合入 v3.5-v3.8 算法修复

- 负载均衡全局联合枚举：贪心卡住时触发 _rebalance_presenters，负责人+主要协助联合搜索，gap 从 6h+ 收敛到 1h 内。
- 状态来回切换保留原分工：已完成任务的 presenter/score/reasoning 完整保留，不再清零覆盖。
- enhance 改为条件式均衡：仅在负载差超阈值时才搬运负责人，以 LLM 分配为基准。
- 均衡后自动重算 score/reasoning，与最终负责人自洽。
- LLM 调用健壮性：配额耗尽秒退、空 key 兜底、ASCII 屏蔽词加单词边界、Planner 兜底自适应团队规模。
- /api/save 同名课程同一秒保存追加计数后缀，不再覆盖历史计划。

## v4.7.2 知识库增强的工时估算

- 新增结构化工时案例库，按任务名称、说明和成果类型检索相似案例。
- Planner 会收到与当前项目相关的基准工时范围；生成后的任务再经过同一知识库校准，AI 与快速草案使用统一标准。
- 成员可用工时只用于判断方案是否超载，不再反向放大或压缩任务本身的预计人时。
- 任务卡显示参考工时范围、可信度和估算依据；用户仍可直接修改最终工时。
- 估时会识别报告字数、多日现场工作、轻量/复杂要求和说明中的明确学时，按 0.5 小时取整。
- 默认分工在不明显破坏技能匹配和成员回避偏好的前提下，尽量将成员负载差控制在 2 小时内；任务粒度无法均摊时给出拆分建议。
- “不超过10000字”等上限不再被当作默认写满；规定活动学时与负责人制作人时分开显示。
- 用户手动修正自动工时后会写入本地反馈；至少积累 3 条相似修正才影响新估时，并使用中位数避免异常值污染。

## v4.6 任务短句与 AI 返回容错

- 文件中的“不要求、无需、不得、只需、即可、至少、不超过、格式为”等内容会归入相关任务说明，不再单独生成任务。
- PDF 切句遗留的孤立括号和兼容汉字会在分析前统一清理，任务名称不再出现残缺右括号。
- 例如“实现文件加密功能；命令行界面即可，不要求使用图形界面”会生成“实现文件加密功能”，后两项只作为验收限制。
- AI 返回 JSON 可读但缺少默认字段、工时写成“4小时”、技能写成逗号文本等轻微问题时，会在本地修复后直接采用，不再次调用模型。
- 只有 JSON 截断或无法安全修复时才使用本地任务蓝图；错误说明会明确列出可能的数据问题。

## v4.5 长课程手册解析

- PDF 文本提取保留页内段落边界，不再把目录、课程介绍、系统操作和实践要求压成一条长句。
- 长手册会先识别真正由学生执行的活动、必须交付物、建议成果和鼓励成果，再生成任务。
- “思政实践”课程手册可提炼出不少于 4 天调研、1 次理论讲座、3 次研讨会及记录、支队调研报告、个人总结报告和 6 分钟汇报 PPT。
- 实践总结推送会继续拆成结构策划、照片与感想、文案、秀米排版、审核排期与投稿；Vlog 会拆成脚本镜头和剪辑审核。
- 个人总结报告会按当前成员逐人生成任务。
- AI 调用失败时会显示可理解的原因，并明确说明文件是否解析成功；文件任务蓝图可直接兜底，不再回退成宽泛阶段名称。
- 对同一份 63 页课程手册，本地要求分析约为毫秒级；主要耗时仍是 PDF 文字提取和单次 Planner 请求，不增加额外 LLM 调用。

## v4.0 工作流

项目现在按以下步骤运行：

`项目信息 → 文件分析（可跳过）→ 可编辑任务拆解 → 确认后自动分工 → 拖拽调整 → 最终方案`

- 任务草案包含类别、预计工时、技能、依赖、执行阶段、开始/截止日期；支持增删、拆分、合并和拖拽排序。
- 页面不再展示内部“类别”字段；新增每项任务的建议参与人数。类别仍在数据层保留以兼容旧方案。
- 只有点击“确认拆解并开始分工”后才会执行人员分配。
- 分工看板支持跨成员拖拽，实时显示任务数、总工时、阶段集中和不均衡提示。
- 上传支持 PDF、DOCX、TXT、Markdown、XLSX、PPTX，单文件上限 15MB；扫描版 PDF 和图片 OCR 暂未支持。
- 文件阶段使用本地文本提取与规则归类，不单独调用大模型；整个首步只在任务拆解时调用一次模型。
- 首次生成和 AI 重新拆解都会先把文件中的核心任务、交付物、格式、限制与评分点传入 Planner，不再只读取文件名。
- 任务名称使用“动作 + 具体对象/成果”，任务说明同时包含处理对象、产出与可检查的完成标准，避免“现场执行与过程调整”等宽泛表述。
- 文件分析仍是本地毫秒级处理，不增加串行模型调用；任务拆解保持一次 LLM 请求。
- 任务卡仅允许从左侧拖动手柄调整顺序，名称、说明和其他字段可正常拖选文字并直接修改。
- 右下角“聊”按钮可围绕当前方案实时询问调整建议。
- AI 调整建议可读取尚未确认的任务草案，也可读取最终分工方案。
- 最终方案恢复任务状态、总体进度、甘特图、时间线、分工矩阵、工作量和报告视图。

## v4.1 工作台与核心服务分层

前端恢复为成熟的“左侧项目配置 + 右侧结果工作区”结构。文件要求在后台分析，
右侧依次承载任务拆解编辑、分工看板和最终结果 Tabs，不再切换多个全屏页面。

核心业务已下沉到 `app/services/project_service.py`：

- `generate_draft`：生成任务草案；
- `mutate_draft`：统一处理新增、修改、删除、拆分、合并和排序；
- `confirm_draft`：校验草案并开始自动分工；
- `apply_manual_assignment`：保存负责人和协作者调整并重算排期；
- `workload_snapshot`：生成统一工作量统计与建议。

Web 页面仅负责展示和把用户操作转换成结构化业务指令。未来接入清小搭时，
OpenAI 兼容适配层可把自然语言转换为同一组 `DraftOperation` 或分工请求，
与当前网页共享 Agent 核心逻辑，不需要复制业务规则。

规划中的分层边界：

```text
网页工作台 ─┐
            ├─> Project Service ─> Planner / Scoring / Timeline / State
清小搭适配层 ┘          （未来实现 /v1/models 与 /v1/chat/completions）
```

## v2.0 更新亮点（2026-07-16 深度审查修复）

本次版本针对全量代码审查发现的 30 项问题进行系统性修复：

- **工时链路打通**：每日工时真正驱动规划，不再有硬编码的假产能。
- **排期更现实**：CPM 改为半天粒度，小任务不再被放大成整天；起始日不会排到过去。
- **导出完整可用**：支持 Markdown / Word / PDF 三种格式导出，普通用户可直接打印。
- **状态闭环**：标记任务「完成/阻塞」会实时重算排期与分工，不再只是视觉标记。
- **安全加固**：修复路径穿越、空成员、负载误报等问题。

详见 [CHANGELOG.md](CHANGELOG.md)。

## 一句话定位

> 别人给你一张**静态分工表**；我们给你一张**可编辑的活协作图**——每个任务带角色化的 QA 归属，计划随现实变化而**实时重算**。

输入「课程信息 + 团队成员 + 截止日」，系统自动：**拆解任务 → CPM 排期 → 技能匹配分配答辩角色 → 生成报告**，并支持随时增删改任务、即时重算。

## 系统架构

```
AssignmentInput (课程 / 成员 / 截止日 / 每日工时)
     |
     v
+-----------+      +-----------+      +------------+      +-----------+
|  Planner  |----->|  Matcher  |----->|  Timeline  |----->|  Reporter |
+-----------+      +-----------+      +------------+      +-----------+
     |                  |                   |                  |
     v                  v                   v                  v
 validate_plan     skill_score        CPM + 日工时折算        FullPlan
 去重/去环/清依赖   enhance/workload   倒排日期 + 浮动天数      |
                                                              |
                    +-----------------------------------------+
                    |
                    v
               B4 动态编辑
               add / remove / update -> 重算 Timeline + Matcher
```

| Agent | 职责 | 实现 | LLM 失败兜底 |
|-------|------|------|-------------|
| Planner | 课程信息 -> 1-8 子任务（按规模弹性） | LLM | 确定性 5 阶段兜底 |
| Matcher | 任务 -> 主讲/主答/辅答 | LLM + B3 评分增强 | B3 确定性贪心分配 |
| Timeline | 任务依赖 -> 倒排日期 | 纯 CPM 算法 | 无需兜底（纯数学） |
| Reporter | 全部结果 -> 答辩报告 | LLM | 纯文本拼接兜底 |

**设计原则**：LLM 负责创造性拆解，确定性算法负责正确性保证（关键路径、技能评分、负载均衡、依赖校验）。每个 Agent 失败都有兜底，主链路永不中断。

## 协作方式

三人轮流负责，每人在自己负责的时间段内可以直接在 main 上做大改。交接前确保 git pull 拉到最新版本，改完 git push 即可。

## 单 Agent 调试

不需要启动 Web 服务，可以单独运行任意一个 Agent 来调试 Prompt 或算法。
详细用法见 [单 Agent 调试指南](docs/单Agent调试指南.md)。

快速示例：
```bash
python -m app.cli planner --course "软件工程" --desc "小组项目" --members "张三:前端,李四:后端" --deadline 2026-08-01
```
