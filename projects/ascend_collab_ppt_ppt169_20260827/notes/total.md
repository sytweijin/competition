# 04_problem
本页说明项目要解决的真实问题。组队完成一个项目，几乎每个人都有过这样的经历：分工靠临时商量，任务边界含糊，有人忙有人闲，临近答辩才发现进度对不上。这背后是四个真实存在的痛点。第一，静态计划表：绝大多数规划工具只在项目开始时生成一张分工表，从那以后就再也不更新，项目一旦变化，这张表立刻过时，团队只能回到群里反复对齐。第二，大模型没有进入流程：多模态能力通常只被当作聊天机器人挂在旁边，结果停留在对话框里，从来没有真正改变团队怎么分工、怎么排期。第三，汇报成本高：成员更新任务状态步骤繁琐，于是大家选择不更新，负责人只能挨个追问进度，信息永远滞后。第四，会议内容难沉淀：录音、录像、白板照片散落各处，没有人愿意二次整理，会上讨论清楚的任务会后依然要靠回忆。

# 05_solution
本页给出解决方案的整体逻辑：我们的答案不是做一个更强的聊天机器人，而是把全模态能力接进一条完整的协作流程，从立项到交付，每一步都有明确的动作和反馈，环环相扣。第一步拍照立项，白板、截图、手绘拍下来就能读懂，直接生成项目需求，不用逐字输入。第二步说话排期，录音直接交给模型，听懂后生成任务草案，不必先转写再粘贴。第三步确认分工，草案可以增删、拖拽、调整，每次改动即时重算排期与负载。第四步成员汇报，免登录点开链接，语音或照片就能交，负责人确认后自动进入计划。第五步群通知触达，状态一变，工作群自动收到通知，每天还有 AI 语音播报今日待办。两条设计原则贯穿始终：LLM 负责创造性拆解，确定性算法负责正确性保证；每个 Agent 失败都有确定性兜底，断网、模型离线时主链路依然可以完整演示。

# 08_plan-engine
本页介绍计划引擎的确定性正确性保证机制。计划是拿来执行的，不是拿来欣赏的，因此我们把引擎拆成两半：AI 负责想得开，算法负责算得准。主链路分为五步：任务拆解、结构化校验、技能匹配分工、CPM 关键路径排期与报告生成。LLM 负责创造性工作——理解自然语言需求、拆解任务、给出工时建议、组织报告表达、提出批判性审查建议，这些没有唯一正确答案，适合大模型发挥；确定性算法负责正确性工作——关键路径与浮动、技能评分、负载均衡、依赖校验、跳过周末与不可用日的日期约束，这些必须精确、可复现，绝不能依赖模型输出的偶然正确。拆解、分工、排期、审查任一环节的 LLM 失败都会自动切换到确定性规则实现，因此演示不依赖模型持续在线。

# 12_feature-overview

# 13_plan-engine-detail
本页详解计划引擎的四项机制。任务拆解方面，系统先判断项目规模：小型项目直接拆解分工，大型项目先拆大模块、由骨干认领、再逐层拆到子任务，最后开放志愿者招募与认领；拆解由 LLM 结合知识库的工时案例生成一到八项弹性子任务，失败时自动切换到确定性拆解规则。工时估算方面，每一项任务都从结构化工时案例库检索参考工时，再结合成员实际情况校准；任务完成后的实际偏差会反馈回知识库，同类任务下次估算得更准。技能匹配方面，按中文、近义词和中英文三种方式匹配技能，把成员排成负责人、主要协助、辅助协助三层角色，每一项分工都给出匹配度评分，为什么选这个人看得见、说得清。负载均衡方面，按成员可用工时与阶段负载自动均衡，避免有人连轴转、有人闲着，均衡后重算评分并说明调整理由。

# 14_cpm
本页介绍 CPM 关键路径排期。算法首先从截止日倒排各任务起止日期，然后计算关键路径与浮动，识别影响整体进度的任务并输出风险提示；排期尊重资源日历，跳过周末与成员不可用日；同时支持手动固定日期，计划可人工微调。右侧甘特示意展示了任务条、里程碑、依赖连线与以金色高亮的关键路径，图中为示意绘制，真实运行界面见第 25 页截图占位。

# 15_dynamic
本页说明动态协作与版本管理能力。计划的价值不在于生成的那一刻，而在于之后每一次变化都能跟得上：人改一步，系统就重算一步，计划永远是现在时。可编辑草案支持增删改、拆分与合并任务；看板支持拖拽分工，改乱了可以一键恢复自动分工；任务状态切换、成员变动、工时调整都会触发排期与分工的自动重算；成员管理可增删成员、调整每日工时、角色与不可用日期，应用后自动重排。版本管理方面，保存即生成版本快照，相似任务形成版本树，支持差异对比与分支回滚，每一次调整都可追溯、可恢复，试错没有代价。大型项目模式按大模块拆解、骨干认领、子任务拆解、志愿者招募与认领多阶段连续推进，骨干认领包含负责人与技能、工时、不可用日期信息。

# 16_report
本页展示汇报触达的四步流程。进度追踪的成本越低，成员越愿意更新；通知触达越自动，负责人越不需要追问，这条链路把汇报变成一件顺手的事。第一步生成 token 链接，token 绑定方案与成员，免登录，打开只看到自己的任务；第二步语音或照片汇报，语音上报状态、工时与备注，交付物拍照即可上传；第三步负责人确认完成，变更进入计划并自动触发即时重算；第四步群通知与今日播报，状态变更自动推送企业微信、飞书、钉钉 Webhook，并由云端 TTS 播报今日待办。关键机制包括全程免登录、自动触达与今日播报：无需注册，手机即可完成；状态变更自动推送，无需人工转发，消息不遗漏；今日播报让团队节奏一目了然。

# 18_section-innovation
这是第四章章节页，提出四个创新点，分别回答四个关键问题：全模态如何从聊天进入真实协作流程、计划结果如何保证正确、系统如何做到完整闭环并全环节兜底、昇腾本地与云端如何统一适配并满足合规要求。

# 19_innovation-1
本页说明创新点一：把多模态模型变成协作流程的入口。先看一个常见的现状：市面上几乎所有多模态应用都把模型放在聊天框里，你问它问题、它回答你，然后就没有然后了；图片识别、语音转写、视频理解都是一个个孤立的按钮，结果永远不会变成团队下一步要做的事。本项目把五种模态接入真实工作流：拍照立项，白板、截图、手绘直接进入任务拆解，系统理解的不只是文字，还有图表、流程和界面；说话排期，录音直接交给模型，听懂后生成任务草案，不需要先转写、再复制、再粘贴；会议旁听，录像边看边听，画面和声音分别理解后合并，自动整理成要点、任务和风险；答辩直连，评委的语音视频点评直接对话，录像附逐帧表现观察。这些能力的共同点，是模型每一次输出都落到工作流的下一个动作上，多模态能力第一次不是附加功能，而是协作这件事的入口。

---

# 20_innovation-2
本页说明创新点二：确定性正确性保证。AI 规划工具最大的问题是输出不稳定：同一个需求，模型这次给三周、下次给五天，今天推荐的负责人和明天不一样；计划是要拿来执行的，不确定性就是成本。所以我们把架构拆成两半——模型负责创造，算法负责正确。LLM 负责理解自然语言需求、拆解任务、给出工时建议、组织报告、提出批判性审查建议，这些没有唯一正确答案，适合大模型发挥；确定性算法负责关键路径与浮动、技能评分、负载均衡、依赖校验、跳过周末与不可用日的日期约束，这些必须精确、可复现，绝不能依赖模型输出的偶然正确。这相当于给 AI 规划加了一条算法安全带：任何 LLM 环节失败都自动切到确定性规则，断网、模型离线时主链路依然完整。

---

# 21_innovation-3
本页说明创新点三：完整协作闭环与全环节兜底。很多作品是一个漂亮的单点 Demo：识别很准、语音很流畅，但离能解决一个问题还差很远；评审时最怕的，是演示到一半模型不可用。所以我们做的不是单点，而是一条闭环——计划生成、成员执行、汇报反馈、通知触达环环相扣——并给每一环都准备了确定性兜底：LLM 拆解失败，用确定性拆解和弹性子任务规则顶上，方案照样生成；分工失败，用规则分工与评分兜底，匹配度依然可解释；排期失败，用算法排期兜底，日期约束依然生效；断网或模型离线，本地保留确定性拆解与导出能力，主链路仍可演示。结果就是：演示不依赖模型持续在线，哪怕模型全挂，核心协作流程照样能走通，这对可运行、可展示的评审要求是实打实的保障。

---

# 22_innovation-4
本页说明创新点四：昇腾本地与云端双后端统一适配。昇腾赛要求统一昇腾环境复现，但 910C 算力紧张，开发期不可能一直占着；我们的做法，是让同一套系统同时支持两种后端，一键切换——评审用本地昇腾证明复现，开发用云端保证进度。本地后端使用昇腾 A3 的 Ascend 910C 与 llama.cpp-omni 运行 MiniCPM-o-4_5-F16，约 16G，本地能直接听、实听实答；云端使用 ModelBest 的 MiniCPM-o-4.5-Realtime API，免费，turn-based 音频先转写再理解，行为经适配层与本地统一。两者通过同一套 WebSocket 协议切换，/api/realtime/status 返回 local 或 map 一键确认。合规方面，当 APP_MODEL_MODE 为 minicpm 且 APP_ALLOW_EXTERNAL_MODELS 为 0 时，全链路仅调用 MiniCPM-o 4.5，不创建任何其他模型客户端；API Key 仅存于 .env，不进入版本库。

# 28_compliance
本页说明合规安全与已知边界。合规与安全方面：模型合规可控，合规模式下全链路仅调用 MiniCPM-o 4.5，不创建任何其他模型客户端；密钥安全，API Key 仅存 .env 不进入版本库；操作可审计，提供多用户 ACL、会话登录、操作审计与版本回滚。已知边界如实说明：8B 模型推理能力有限，演示主打感知与流程闭环，不做高难度推理；910C 本地 TTS 有已知算子问题，语音播报走云端 API；云端音频表现为转写，已通过适配层统一行为；llama-omni-server 仅支持单活跃会话，演示前需预检暖机。工程态度是能力边界如实标注，不夸大模型能力，确保评审现场演示可预期、可复现。

# 29_summary
总结页重申核心价值：把 MiniCPM-o 4.5 从聊天机器人变成真实协作流程的入口，拍照立项、说话排期、确认分工、语音与照片汇报、群通知，全链路由全模态能力驱动。四个关键词各有完整含义：全模态入口——五种模态第一次进入真实协作流程，而不是停在聊天框里；确定性正确——LLM 负责创造、算法负责正确，计划结果可复现、不受模型波动影响；完整闭环——从计划到执行、汇报、触达环环相扣，任何环节失败都有确定性兜底；昇腾可复现——本地与云端双后端统一适配，统一昇腾环境可以复现。展望方向包括：接入云端全双工实时语音与视频对话体验；企业微信应用消息定向推送，通知更个性更及时；课程、赛事、企业项目等场景模板与知识库经验持续沉淀，工时估算与分工建议越用越准。作品版本为 v7.1，提交于 2026 年 8 月，面向华为昇腾创新应用赛道。
